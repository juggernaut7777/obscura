## 2025-02-28 - [Avoid N+1 Stat Calls with os.scandir]
**Learning:** Using `pathlib.Path.iterdir()` combined with `.stat().st_mtime` to sort files by modification time leads to N+1 system calls (one for reading the directory and N for stat). `os.scandir()` caches file attributes, making it significantly faster for this operation (~50% faster in a directory of 100 files). This is a codebase-specific performance pattern to watch for, especially when dealing with many files.
**Action:** Use `os.scandir()` instead of `iterdir()` when iterating over directories and immediately accessing file attributes like `st_mtime`.

## 2025-02-28 - Node.js API Event Loop Blocking via Sync I/O
**Learning:** Found Next.js API routes (e.g., `storefront/src/app/api/admin/warehouse/route.js`) using synchronous fs methods (`fs.readdirSync`, `fs.readFileSync`) to read metadata and large base64 thumbnails. In a Node.js server, this blocks the main event loop, significantly delaying or halting responses to other concurrent requests. A benchmark showed a 50ms block for 20 heavy items vs 13.95ms max block for async processing. Additionally, sequential processing was slower overall than using `Promise.all()`.
**Action:** Always replace `fs.*Sync` operations in Next.js API routes with their `fs/promises` equivalents. Use `fsPromises.readdir(..., { withFileTypes: true })` to prevent N+1 stat calls to check `isDirectory()`, and use `Promise.all()` to map over dirents concurrently.
