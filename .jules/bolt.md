## 2025-02-28 - [Avoid N+1 Stat Calls with os.scandir]
**Learning:** Using `pathlib.Path.iterdir()` combined with `.stat().st_mtime` to sort files by modification time leads to N+1 system calls (one for reading the directory and N for stat). `os.scandir()` caches file attributes, making it significantly faster for this operation (~50% faster in a directory of 100 files). This is a codebase-specific performance pattern to watch for, especially when dealing with many files.
**Action:** Use `os.scandir()` instead of `iterdir()` when iterating over directories and immediately accessing file attributes like `st_mtime`.
## 2025-02-28 - [Async FS & Promise.all for API Performance]
**Learning:** Using synchronous `fs.*Sync` methods inside a sequential loop in a Node.js API route blocks the event loop, causing poor performance and scaling issues, particularly when reading multiple files and directories (e.g., reading metadata and image files in a warehouse directory). Refactoring to asynchronous `fs.promises` combined with `Promise.all` significantly speeds up response times by executing I/O bound operations concurrently.
**Action:** In Node.js server environments, always avoid `fs.*Sync` operations. Use asynchronous file system operations (`fs.promises`) alongside `Promise.all` for parallel processing of independent I/O tasks to maximize throughput and responsiveness.
